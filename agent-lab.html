Implemented application · Experimental workflows

Retrieve. Generate. Check.

  1. 01 / RETRIEVE

    Inspect candidates

    E5 semantic matching and lexical anchors rank passages from the prepared corpus.

  2. 02 / GENERATE

    Use supplied evidence

    The server-assisted workflow asks a model to answer from the retrieved passage.

  3. 03 / VERIFY

    Check support and coverage

    A model assesses claims and missing concepts; software also checks source quotations.

Verification is model-dependent. A matching quotation and a model approval do not prove factual correctness.

Bounded evidence fusion

When one passage
is not enough.

A missing concept can trigger one recovery attempt. ParancU reranks the corpus, and a complement check looks for another passage that supplies missing support.

The original and selected complementary chunk are supplied together for fresh generation and verification. This is a two-chunk workflow, not an unlimited retrieval loop or general multi-document planner.

Choose a processing mode

Understand where data goes.

Import a prepared corpus

Imported corpora stay in browser memory until the page is left or reloaded. Browser E5 embeds the query and retrieves evidence without OpenAI or an API key.

Generate/Verify is unavailable for imported corpora in this mode. Model assets are loaded by the browser.

Prepare a TXT document

TXT text is sent to the server and stored temporarily as a prepared corpus. Preparation and generated/verified answers send relevant content to OpenAI using the supplied session key.

The web key is held in server-session memory. Optional telemetry is restricted by code to operational metadata. These mechanisms are not a privacy certification.

The ParancU iOS privacy policy describes the mobile app. Its on-device processing boundary must not be applied to Agent Lab’s server-assisted workflow.

Practical boundaries

  • TXT preparation and prepared JSON exchange are implemented in the web app.
  • There is no conversation memory or token streaming in the audited version.
  • Preparation has no checkpoint/resume mechanism; retry can repeat metadata calls.
  • Research results do not establish broad browser parity or dependable sufficiency judgments.
